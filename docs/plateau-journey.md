# PLATEAU 都市の旅

URL: `http://127.0.0.1:4317/plateau-test.html?journey=1`

既存の `npm run preview` を使用。通常の `plateau-test.html` とタヌキゲームはそのまま利用できる。

## 構成

- `src/plateau-test.js`: `journey=1` の場合のみ専用モードを作成。通常ビューアのクリック遷移・ホバーとは排他。
- `src/plateau-journey.js`: ターゲット、北を上に保つ追従、俯瞰、駅名、進捗、再生制御、読み込み完了判定。
- `src/plateau-route.js`: 駅位置と近似経路。東京・神田は既存PLATEAUの駅フィーチャ座標、秋葉原は既存ビューア原点を使用。
- `plateau-journey.css`: 専用モードの案内表示。

画像の赤線はユーザーが描いた目印であり、軌道データではない。途中の経路と高度48m（楕円体高）は案内用に簡略化したもの。測量済みの線路中心線・軌道高として扱わない。PLATEAU本体の座標・縮尺・タイル・境界は変更していない。

## 読み込みと再生

現在の登録済み末端タイル（建物5、道路29、橋梁3、水1、植生4）を補助カメラで先に要求し、42枚が読み込まれて1秒安定してから出発を許可する。走行中も要求を維持し、通過した街を隠さない。実際の描画には追従カメラを使用する。全データの読み込み・展開を先に行うため、初期待機とメモリ使用量は必要。

標準は旧2倍の52m/s、3倍は78m/sを上限とし、出発・終点付近は減速。神田で2.5秒停留。タブが非表示になると停止する。読み込み失敗時は出発を許可せず、対象を表示する。

左ドラッグでOrbitControlsの角度を変更できる。右ドラッグすると地図の自由移動に切り替わり、ターゲットに追従しない。「追従する」「全体を見る」でそれぞれ既定カメラへ復帰。後方視点は高・中・低（注視点から高さ600/260/100m）の3段階。

建物はターゲットの約1km前方で、下から上へ表示されるシェーダー演出を使用。座標やスケールは変更せず、一度表示した部分は隠さない。全体表示に切り替えた場合は全域を表示して維持する。

到着駅の背景色を濃くする。秋葉原到着後の駅ラベルはクリック可能になり、既存ビューアと同じ真上姿勢への移動・回転（各1.8秒）、0.9秒の間、1.8秒のズームと白フェードを経て既存のタヌキゲームへ遷移する。青いホバーは使用しない。

- 確認時のブラウザエラー・警告なし。
- `node --test tests/plateau-route.test.js` の2テスト成功。

追加検証: `tests/plateau-camera.html` でカメラ・実OrbitControlsへの合成ポインター入力・到着姿勢・フェード等12件成功。実ブラウザで3倍速走行、低い後方視点、秋葉原クリックからタヌキゲームの表示まで確認。左右ドラッグは自動入力テストで確認しており、物理マウスでの手動確認とは区別する。

経路はユーザーの黒線の通路へ修正し、読み込み済み建物メッシュへ2m間隔の下向きレイで照合した。交差は東京駅の無壁舎（data11 ID57）、神田駅（data2 ID82）と付近の運輸施設の無壁舎（ID454）、秋葉原駅と無壁舎（data0 ID248/287/291）。他の一般建物との交差はこのサンプリングでは検出されなかった。連続した全点の数学的保証ではない。

残る制約: 正確な軌道との一致・軌道高は未検証。元データの空白範囲は残る。ターゲットの位置マーカーは建物に隠れない案内表示であり、物理的な遮蔽を再現するものではない。低性能端末・オフライン・長時間実行時の性能は未検証。既存のCDN依存を維持している。
